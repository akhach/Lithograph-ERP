# 1. Purpose

This document defines the implementation sequence for the Clients module.

The Clients module manages Lithograph customers.

After this phase, the ERP must be able to:

```text id="cdzd9m"
Create Clients

Generate Client Business IDs

Edit Clients

Activate/Deactivate Clients

Search Clients

Display Client Details

Use Clients later in Project creation
```

---

# 2. Module Boundary

Clients owns:

```text id="zq95ms"
clients.clients
```

Projects will later reference Clients through:

```text id="r8lx79"
projects.projects.client_id
```

The Clients module does not own Projects.

# 20. Task 2 — Business ID Infrastructure

Clients are the first module requiring production Business ID generation.

Implement the shared numbering mechanism carefully.

---

# 21. Numbering Service Scope

A narrow numbering component should eventually support:

```text id="0ojzmq"
Clients

Projects

Orders
```

Do not build a generic enterprise numbering designer.

---

# 22. Client Sequence

Client numbering sequence:

```text id="p2uk48"
1
2
3
...
```

displayed as:

```text id="mjqqb9"
CL-000001
CL-000002
CL-000003
```

---

# 23. Zero Padding

Use:

```text id="ec5gsr"
6 digits
```

after the prefix.

---

# 24. Sequence Gaps

Gaps are acceptable.

Example:

```text id="s31r21"
CL-000125

CL-000127
```

with no `CL-000126` is valid.

Do not try to reuse gaps.

---

# 25. Concurrency Safety

Two simultaneous Client creates must never receive the same Business ID.

---

# 26. Prohibited Numbering Strategy

Never use:

```text id="qsxx16"
SELECT MAX(existing_number) + 1
```

because it is race-prone.

---

# 27. Acceptable Numbering Mechanisms

Use an atomic PostgreSQL-backed approach such as:

```text id="ttbu9j"
PostgreSQL sequence

Dedicated numbering table with row locking

Other transactional atomic mechanism
```

The exact implementation should also support future yearly Project/Order numbering.

---

# 28. Numbering Architecture

Prefer one simple reusable backend abstraction.

Conceptually:

```text id="igf2n9"
IBusinessIdGenerator
```

or equivalent.

Do not expose numbering implementation to Controllers.

---

# 135. Final Clients Principle

The Clients module should answer:

```text id="6g0lhv"
Who is the customer?
```

```text id="pbr3ff"
How can Lithograph contact them?
```

and:

```text id="8ccefl"
Which stable Business ID identifies them?
```

It should provide the foundation for:

```text id="t5sf75"
Client
   ↓
Project
```

without becoming a CRM or accounting system.

The central rule is:

```text id="l80o6f"
Client data identifies the customer.

Projects describe the work done for them.
```
